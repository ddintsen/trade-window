# Deploying the realms on the Onyx testnet

Only the owner runs these steps: every transaction here is signed with the
owner's own key, on the owner's own machine. Nothing in this repository holds
a key, and no one else should.

## From Adena, on the site (no command line)

The site's unlisted `/launch` page publishes both realms from the owner's own
Adena account, under the owner's name or address. The account that publishes
is the rooms admin and treasury from the start, so there is nothing to hand
over afterwards. Three confirmations in Adena:

1. Open `https://tradewindow.xyz/launch` in the browser with Adena, connect the
   owner's account and switch it to Onyx when the page asks.
2. Register the name (`nym-tradewindow001` is filled in), or choose the
   address instead.
3. Publish rooms, then board. Onyx parks new code until its reviewer enables
   it. Check the activation time in the [Onyx package approval service](https://gpas.onyx.testnets.gno.land/). The page shows each realm as
   live. Publishing both locks about 8 GNOT of storage deposit and costs well
   under 1 GNOT in fees (rooms used 98.6 million gas on a local chain with the
   same parameters; the page allows 200 million).
4. The page shows the admin and treasury (both "you") and the five site
   settings: copy them into Vercel (Production and Preview) and deploy the
   site again.

The page sends exactly the repository's realm files without their tests
(`apps/web/src/lib/chain/realm-source.ts`, generated by
`apps/web/scripts/embed-realms.mjs` and checked by a unit test), the same as
`scripts/gno/deploy.sh`. `apps/web/e2e/launch.spec.ts` runs the whole page on
a local chain.

## If Onyx reports a transaction decode error

Onyx requires canonical transaction encoding as of November 17, 2026. Clients
built against Gno versions before 1.7.1 can return `tx decode error` before the
package runs. Use a signer built with Gno 1.7.1 or later. Gno MCP 0.13.1 builds
against Gno 1.8.0.

- [Onyx release and client requirements](https://github.com/gnolang/gno/releases/tag/v1.8.0-rc.1)
- [Gno MCP 0.13.1 release](https://github.com/gnoverse/gno-mcp/releases/tag/v0.13.1)

To keep `nym-tradewindow001` under the project owner, use the
[Trade Window launch page](https://tradewindow.xyz/launch) with Adena on
Onyx. The wallet signs under the owner's account and the page checks that
each realm becomes callable before it reports success.

## From the command line

Onyx (`onyx-1`) runs the same code as gno.land mainnet, with a faucet and
open transfers. What works there works on mainnet.

## What you need

- `gnokey`, built from the `chain/mainnet` branch of github.com/gnolang/gno:

  ```bash
  git clone --depth 1 --branch chain/mainnet https://github.com/gnolang/gno
  cd gno && make install.gnokey
  ```

- A key: `gnokey add tradewindow` creates one (write the mnemonic on paper
  and keep it offline), or `gnokey add --recover tradewindow` imports an
  existing one. `gnokey list` shows its `g1` address.
- About 15 test GNOT from https://faucet.gno.land. Measured on a local chain
  with gno.land's default storage price, the deploy locks about 5.2 GNOT of
  storage deposit for the rooms realm and 2.5 GNOT for the board, plus the
  network fees.

## Steps

1. Optional, once: register the readable namespace, so the realms live at
   `gno.land/r/nym-tradewindow001/...` instead of under the `g1` address.

   ```bash
   scripts/gno/register-name.sh tradewindow nym-tradewindow001 onyx
   ```

2. Deploy both realms. Use the name from step 1, or your `g1` address.

   ```bash
   scripts/gno/deploy.sh tradewindow nym-tradewindow001 onyx
   ```

   Onyx parks new packages until its approval oracle enables them.
   The script prints the site settings after both realms become callable.
   Running it again skips a realm that is already deployed.

3. Give the site the five values the script printed, in the Vercel project
   (Settings, Environment Variables, for Production and Preview), then
   redeploy:

   ```text
   NEXT_PUBLIC_GNO_CHAIN_ID=onyx-1
   NEXT_PUBLIC_GNO_RPC_URL=https://rpc.onyx.testnets.gno.land:443
   NEXT_PUBLIC_GNO_WEB_URL=https://onyx.testnets.gno.land
   NEXT_PUBLIC_GNO_ROOMS_PATH=gno.land/r/nym-tradewindow001/rooms
   NEXT_PUBLIC_GNO_BOARD_PATH=gno.land/r/nym-tradewindow001/board
   ```

4. Check: the realms render at
   `https://onyx.testnets.gno.land/r/nym-tradewindow001/rooms` and `.../board`;
   on the site, connect Adena on Onyx, open a room with a second account,
   deposit on both sides, lock twice, and see the swap.

The deploying key becomes the rooms admin. The admin can pause new rooms,
deposits and locks with `SetPaused`, and hand the role over with
`ProposeAdmin` and `AcceptAdmin`. It can never move anyone's deposit, and
withdrawing, unlocking and cancelling always work.

## Trade chat

The chat under each trade keeps its messages in Redis, not on chain. In the
Vercel Marketplace open Upstash for Redis
(https://vercel.com/marketplace/upstash/upstash-kv), add it to the
trade-window-final project for Production and Preview, sign in to Upstash,
create a database and pick its plan, then deploy the site again. The
integration sets `KV_REST_API_URL` and `KV_REST_API_TOKEN` (the
`UPSTASH_REDIS_REST_*` pair works too); nothing else is needed. Without
them the chat says it is not switched on yet and everything else works.
Messages stay 30 days after a room's last one, at most 200 per room.

## Later: mainnet and a .gno name

- Mainnet (`gnoland-1`) started with GNOT transfers locked, which also locks
  GNOT deposits into rooms. The scripts refuse mainnet unless
  `CONFIRM_MAINNET=yes` is set, and that should wait until transfers open.
- `.gno` names come from GNS, which is on the Pearl testnet only. When it
  reaches Onyx or mainnet, register `tradewindow` there to get
  `tradewindow.gno`. Nothing in the realms depends on it.

## По-русски: выкладка реалмов в тестнет Onyx

### Из Adena, на сайте (без командной строки)

Скрытая страница `/launch` выкладывает оба реалма из вашего аккаунта Adena,
под вашим именем или адресом. Кто выкладывает, тот сразу админ и казначей
комнат, передавать роли не нужно. Три подтверждения в Adena:

1. Открыть `https://tradewindow.xyz/launch` в браузере с Adena, подключить
   свой аккаунт и переключить его на Onyx, когда страница попросит.
2. Зарегистрировать имя (`nym-tradewindow001` уже вписано) или выбрать адрес.
3. Выложить rooms, потом board. Onyx держит новый код, пока проверяющий его
   не включит. Время активации показывает [сервис Onyx](https://gpas.onyx.testnets.gno.land/); страница показывает, когда реалм
   работает. Обе выкладки блокируют около 8 GNOT залога за хранение и стоят
   меньше 1 GNOT комиссий.
4. Страница покажет админа и казначея («you») и пять настроек сайта: вписать
   их в Vercel (Production и Preview) и передеплоить сайт.

### Чат сделки

Чат под каждой сделкой хранит сообщения в Redis, не в сети. В Vercel
Marketplace открыть Upstash for Redis
(https://vercel.com/marketplace/upstash/upstash-kv), добавить к проекту
trade-window-final для Production и Preview, войти в Upstash, создать базу и
выбрать тариф, потом передеплоить сайт. Интеграция сама задаёт
`KV_REST_API_URL` и `KV_REST_API_TOKEN` (пара `UPSTASH_REDIS_REST_*` тоже
подходит), больше ничего не нужно. Без них чат пишет, что ещё не
включён, а всё остальное работает. Сообщения живут 30 дней после последнего,
не больше 200 на комнату.

### Из командной строки

Все шаги выполняет только владелец, своим ключом, на своём компьютере. В
репозитории нет ни одного ключа, и передавать его никому не нужно.

Что понадобится:

- `gnokey` из ветки `chain/mainnet` (команды выше, в разделе «What you need»).
- Ключ: `gnokey add tradewindow` создаст новый (мнемонику запишите на бумаге
  и храните офлайн) или `gnokey add --recover tradewindow` восстановит
  существующий. Адрес `g1…` покажет `gnokey list`.
- Около 15 тестовых GNOT с https://faucet.gno.land. Сама выкладка
  блокирует примерно 5,2 GNOT залога за хранение у реалма комнат и 2,5 GNOT у
  доски, плюс комиссии (замерено на локальной сети со стандартной ценой
  хранения gno.land).

Шаги:

1. По желанию, один раз: зарегистрировать имя, чтобы адреса были
   `gno.land/r/nym-tradewindow001/...`, а не с `g1`-адресом:
   `scripts/gno/register-name.sh tradewindow nym-tradewindow001 onyx`
2. Выложить оба реалма:
   `scripts/gno/deploy.sh tradewindow nym-tradewindow001 onyx`
   Onyx держит новые пакеты в ожидании проверки. Скрипт напечатает пять
   настроек сайта, когда оба реалма доступны. Повторный запуск пропустит то, что уже
   выложено.
3. Вписать эти пять значений в Vercel (Settings, Environment Variables, для
   Production и Preview) и передеплоить сайт.
4. Проверить: реалмы открываются на
   `https://onyx.testnets.gno.land/r/nym-tradewindow001/rooms` и `/board`, а на
   сайте сделка проходит между двумя аккаунтами Adena.

Ключ, которым выкладывали, становится админом комнат. Админ может только
поставить новые комнаты, депозиты и локи на паузу и передать эту роль. Чужие
депозиты он не трогает, а вывести, снять лок и отменить комнату можно всегда.
